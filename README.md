# VulMan Synthetic Chaining Artifact

Reproducibility package for the synthetic experiments reported in the TDSC manuscript. This package contains no company database, production vulnerability records, real organizational hostnames or IP addresses, tickets, credentials, or network configuration. All assets, synthetic hostnames, findings, routes, capabilities, costs, and ground-truth edges are generated by the included code.

The artifact contains two separate studies:

- **Multiscale campaign:** 240 synthetic scenarios, 1,200 policy records, 3,600 timed executions, scope/evidence ablations, missing-route cases, and graph-scaling measurements.
- **Hostname/DC smoke test:** 50 deterministic seeds, 300 generated assets, and 600 generated finding occurrences. DC tags stratify a synthetic route generator but are never used as proof of connectivity. This is a software smoke test, not a validation of real attack paths.

## Contents

- `multiscale_chaining.py`: evidence-qualified graph model and node separator.
- `run_multiscale_experiments.py`: full synthetic campaign generator and runner.
- `verify_multiscale.py`: independent replay of stored decisions and topology controls.
- `test_multiscale_chaining.py`: 16 unit tests.
- `run_synthetic_tag_smoke.py`: seeded hostname/data-center integration smoke test.
- `requirements.txt`: sole third-party dependency for these experiments.
- `reference-results/`: compact campaign tables, summary, source/output manifest, and tag-smoke JSON.
- `LICENSE`: PolyForm Noncommercial 1.0.0 for source code.
- `LICENSE-DATA.md`: CC BY-NC 4.0 for documentation and synthetic results.

The complete scenario and decision JSON files are intentionally not checked into Git: the canonical scenarios and missing-route decisions are large (hundreds of megabytes), and the runner regenerates them from fixed seeds. The compact reference tables and manifest preserve the manuscript summaries and source/output hashes.

## Requirements

- Python 3.10 or newer; the canonical campaign was run with Python 3.13.14.
- NetworkX 3.6.1.
- Disk space for the full generated campaign (approximately 1 GB or more recommended).

Install the pinned dependency in a virtual environment:

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

## Quick Checks

From this directory:

```powershell
.venv\Scripts\python.exe -m unittest -v
.venv\Scripts\python.exe run_synthetic_tag_smoke.py --seed 20261008 --seeds 50 --output generated-tag-smoke\random_tag_smoke.json
```

The smoke test asserts that supported transitions enter both graphs, unknown transitions enter only the upper graph, known blocked routes are excluded even when tags group assets, and each upper-graph separator disconnects its modeled target. The summary JSON reports the seed and generator-defined outcomes. It is not an estimate of enterprise connectivity.

## Reproduce the Full Campaign

Use fresh, nonexistent output directories. The full campaign writes large synthetic JSON files and takes longer than the quick checks:

```powershell
.venv\Scripts\python.exe run_multiscale_experiments.py --output generated-multiscale
.venv\Scripts\python.exe verify_multiscale.py --results generated-multiscale --output independent-validation
```

The verifier checks the source and output hashes, recalculates selected-action costs and residual reachability with adjacency-list traversal, and runs topology controls. The runner records wall-clock timings; these vary by machine and workload. Compare deterministic scenario structures, decisions, costs, and reachability, not exact timing values or timestamps.

The full multiscale runner currently exposes only the canonical 20-seed-per-family design; it has no reduced-seed command-line option. The quick checks above exercise the model and tag adapter without generating the large campaign outputs.

## Interpretation and Limitations

1. The candidate universe and capability semantics are supplied by the generators. The experiments do not infer attack chains from scanner text or validate edge semantics against enterprise observations.
2. The exact minimum separator optimizes the declared synthetic objective. It is not evidence of operational superiority over deployed vulnerability-management systems.
3. Unknown-route upper-graph guarantees require a complete candidate universe, correct known facts, and successful treatments. They do not cover omitted vulnerabilities, false observations, or failed remediation.
4. DC membership influences only synthetic route-sampling probabilities in the smoke test. It never creates a route edge by itself.
5. Synthetic costs, scores, and route probabilities are arbitrary design parameters, not measured labor, money, CVSS/EPSS, attack likelihood, energy, or emissions.
6. The artifact is not a reproduction package for confidential CIFRE data. No organizational records are included or required.
